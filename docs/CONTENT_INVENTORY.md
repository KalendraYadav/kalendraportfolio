## 1. Content Policy & Verification Legend

To guarantee professional credibility, this inventory distinguishes clearly between **verified facts**, **items requiring confirmation**, and **development placeholders**.

### Status Legend
- `[VERIFIED]`: Confirmed factual data ready for production deployment.
- `[PENDING CONFIRMATION]`: Real item that requires final text or URL confirmation from Kalendra.
- `[PLACEHOLDER ACCEPTABLE]`: Structural placeholder permitted during initial development, but must be replaced or omitted prior to launch.
- `[OPTIONAL]`: Value that enhances the portfolio if available, but can be cleanly omitted without harming UX.

## 5. Candidate Projects Inventory

Each project must satisfy the standard **Project Content Schema**:
- **Title**: Clean project name.
- **Tagline**: One-sentence punchy elevator pitch.
- **Problem Statement**: What real problem does this solve?
- **Engineering Architecture**: Key subsystems, data flow, and technical stack.
- **Key Challenges & Solutions**: 1–2 specific technical hurdles overcome.
- **Tech Stack Pills**: Array of technology names.
- **Status Badge**: `[RELEASED / LIVE]`, `[OPEN SOURCE]`, `[CASE STUDY]`, or `[IN ACTIVE DEVELOPMENT]`.
- **Repository URL**: Verified link to GitHub (omitted if private).
- **Live Demo URL**: Verified link to public URL (omitted if unverified).
